- 2026-04-23: Fix Model Download Crash in Frozen (Windowed) Build — implemented and automated validation recorded. Root cause confirmed: the PyInstaller windowed build (`console=False` in `spkup.spec`) leaves `sys.stdout` / `sys.stderr` as `None`, and `huggingface_hub.snapshot_download` uses `tqdm`, which writes to `sys.stderr` and raised `AttributeError: 'NoneType' object has no attribute 'write'`. The user reproduced this while downloading the Medium model from the compiled build; Tiny and Small had only been exercised from a dev terminal, masking the issue. Fix: `src/spkup/__main__.py` now calls `_ensure_std_streams()` in `_bootstrap()` before DLL setup and logging configuration, redirecting any `None` standard stream to `os.devnull`; `src/spkup/model_manager.py` `_ModelDownloadWorker.run` now calls `huggingface_hub.utils.disable_progress_bars()` (guarded by `try/except`) before `snapshot_download`, so downloads do not depend on a live stderr stream. New regression tests added to `tests/test_model_manager.py`: `test_ensure_std_streams_replaces_none` forces both streams to `None` and asserts they become writable after bootstrap, and `test_model_download_worker_disables_progress_bars` verifies `disable_progress_bars` is called before `snapshot_download` and that the worker emits `finished` without errors. Automated validation: `$env:PYTHONPATH='src'; .\.venv\Scripts\python -m pytest tests/test_model_manager.py -q` passed 9/9, and `$env:PYTHONPATH='src'; .\.venv\Scripts\python -m pytest tests/ -q` passed 164/164. Manual verification of end-to-end Medium (and ideally Large-v3) download from a freshly rebuilt windowed PyInstaller artifact is still pending.
